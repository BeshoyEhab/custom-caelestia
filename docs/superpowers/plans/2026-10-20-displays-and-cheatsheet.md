# Display Switcher + Dynamic Cheat Sheet Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a SUPER+P display switcher (main screen, duplicate, extend with placement, workspace pinning) and a SUPER+/ dynamic keybind cheat sheet, both native Quickshell modules.

**Architecture:** Pure logic (layout math, config-file generation, keybind parsing) lives in `.js` files that are unit-tested with `node`. A `qs.services.Displays` singleton owns hyprctl state and persistence (`~/.config/hypr/monitors.lua`, `~/.config/hypr/workspaces.lua`), applying by writing those files and running `hyprctl reload` — the same contract nwg-displays 0.4.3 uses. Two full-screen layer-shell windows (`modules/displays`, `modules/cheatsheet`) render the UI and are toggled through IPC + `CustomShortcut`.

**Tech Stack:** Quickshell (Qt6 QML), Hyprland 0.56 Lua config, `hyprctl` (`eval`, `monitors all -j`, `binds -j`, `reload`), `node` (tests only).

**Spec:** none — decisions were made in-session; recorded in "Decisions" below.

## Decisions (made during brainstorming)

- SUPER+P opens one compact Windows-style projection picker. Modes: `main` (main only), `duplicate`, `extend`, `second` (second only). Extend adds a 4-way placement (left/top/right/bottom).
- Main screen = stored preference, else the monitor at layout `0x0`, else focused, else first. Setting a new main repositions it to `0x0`.
- Workspace pinning = one workspace number per secondary output, written as `hl.workspace_rule({ workspace = "N", monitor = "<name>", default = true })`; the existing rule for that workspace is replaced, other rules preserved.
- `hyprctl keyword` is dead under Hyprland's Lua parser (`keyword can't work with non-legacy parsers`). Runtime changes go through file write + `hyprctl reload`. `hl.on("hyprland.start")` guards exec-once, so reload is safe.
- Cheat sheet is built from `hyprctl binds -j` on every open, so it is always current. Description prefix before `:` becomes the category. All `--description`-less binds are hidden.
- SUPER+Slash is currently "Toggle OSD"; the cheat sheet takes it and OSD moves to SUPER+Shift+Slash.
- Overview rework is NOT in this plan (phase 3, needs its own design conversation).

## Global Constraints

- Edit BOTH `<repo>/shell/` and `~/.config/quickshell/caelestia/` (deploy with `./install.sh --update`; `qs -c caelestia` loads the user copy). Machine-specific Hyprland files (`monitors.lua`, `workspaces.lua`) are runtime-generated and must stay in `.updateignore`.
- Never touch `shell/upstream/`.
- Colour tokens only (`Colours.palette.m3*`); any file using `Colours` must `import qs.services`.
- No `pragma ComponentBehavior: Bound` in Bar.qml (unrelated, but do not disturb).
- `monitors.lua` must be required AFTER `hyprland.general` (whose wildcard rule re-enables everything) and BEFORE `custom/` (user overrides win).
- Lua output format must match nwg-displays 0.4.3 byte-for-byte in structure so both tools can share the files:
  - `hl.monitor({\n    output = "X",\n    mode = "WxH@R",\n    position = "XxY",\n    scale = 1,\n    mirror = "Y"\n})`
  - `hl.workspace_rule({\n    workspace = "2",\n    monitor = "HDMI-A-1",\n    default = true\n})`
- Every generated file starts with `-- Generated by custom-caelestia on <date>. Do not edit manually.\n`.
- Tests must not disturb the live session; the e2e test is opt-in via `DISPLAYS_E2E=1` and uses `hyprctl output create headless`.
- Node is a test-only dependency.

## Review Focus

1. **No second monitor connected** — SUPER+P must still open, show the single display, and not crash or write a config that disables the only output.
2. **Mirroring an output, then reloading** — a mirrored virtual output can be left unremovable by `hyprctl output remove`; the generated config must not rely on removal, only on explicit `disabled = true` / mirror rules.
3. **Reload re-enables a "main only" disabled output** — general.lua's wildcard `monitor=,preferred,auto,1` runs first; if ordering breaks, the user's "main only" silently becomes extended. Owning task: 5.
4. **Changing the workspace pin twice** — rules accumulate in the file; the old rule for that workspace must be replaced, never duplicated.
5. **A keybind with no description, a mouse bind, or a submap bind** — the cheat sheet must skip/annotate them instead of rendering an empty row or claiming a duplicate SUPER binding.

- [ ] **Step 3: Implement `shell/services/DisplayMath.js`**

Top of file: `.pragma library`. Implementation notes the signature does not decide:
- `layout` builds the main rule first: `{output: main.name, mode: mainModeString, position: "0x0", scale: main.scale}`; `mainModeString` preserves the monitor's exact current mode when its current width/height/refresh is known, else `preferred`.
- Non-main outputs are `{output, disabled: true}` in `main` mode; in `second` mode the chosen secondary is enabled at `0x0` and everything else disabled; in `duplicate` the secondary is enabled with `mirror: main.name` and `position: "0x0"`.
- Positions for `extend` are computed in logical pixels using `logicalSize` (never raw `width`).
- `detectMode` ignores disabled monitors for counting, and returns `second` when exactly one monitor is active and it is not `mainName`.
- `parseWorkspaceRules` matches `workspace\s*=\s*"([^"]+)"`, `monitor\s*=\s*"([^"]+)"`, and `default\s*=\s*true` blocks only.
- `pickMain` order: preferred if it exists and is not disabled → monitor with `x === 0 && y === 0` → focused → first non-disabled.
